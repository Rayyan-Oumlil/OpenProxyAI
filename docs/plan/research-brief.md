## Anis Oumlil's spec ("Enterprise AI Gateway", EIAG) key requirements
- One conversation, many backends: gateway owns a provider-independent Canonical Conversation State (conversation id, tags, history, persona, approved memories, data classification, routing decisions); models are execution engines; per-turn dynamic model routing.
- Minimum-necessary context: build a provider-specific Context Package per call; new authorization/context decision whenever model/provider/tool/MCP boundary changes; audit which context elements were sent.
- Routing separate from authorization; data-classification-aware (confidential -> internal LLM only); failover only to an authorized alternative; deterministic security boundaries, adaptive routing inside them.
- Capability-based routing (GENERAL_REASONING, CODE_GENERATION, CONFIDENTIAL_REASONING ... mapped to authorized models); behavior policy (creativity/determinism) translated per provider.
- Service catalog / LLM registry / MCP registry / API registry with owner, allowed data classes, geography, risk rating, retention, training-on-data flag.
- Memory tiers: session, user, team, enterprise, facts, RAG; chat history never auto-becomes enterprise truth; feedback-to-knowledge pipeline needs approval/sanitization/poisoning checks.
- MCP security: OAuth for HTTP transport, audience binding, never pass-through bearer tokens; threat list (tool poisoning, rogue MCP servers, excessive agency...); SIEM events (AI-DLP-BLOCK, AI-UNAUTHORIZED-MCP ...) via syslog/CEF/JSON/OTel; RBAC+ABAC+PBAC+risk-based authorization; policy decision point using open policy mechanisms; sync vs async security checks.
- Collaboration: private / shared / team knowledge / enterprise knowledge; user education messages instead of silent blocking.
- Admin console map: Dashboard, AI Services(chat/LLMs/MCP servers/tools/APIs), Identity & Access, Policies (model/DLP/MCP/API/cost/risk), Security, Knowledge, Operations, Audit.
- Deployment: containerised/K8s, central control plane + distributed gateways, DMZ external gateway vs internal gateways, DNS/SASE transparent redirect of public GenAI domains to the gateway (network-integration heavy).
Vision doc (marketing, lower priority): "Slack for AI"/CollabAI, voice/hands-free for factories/hospitals, family/school packages, personalization from votes, multi-model orchestration (draft->review->validate).

## 90-day go-to-market without paid cloud
- Days 1-14: decide name/domain (about $15, the only unavoidable cost); one-command seeded local demo (`docker compose up` in under 5 minutes); recorded 3-minute demo (PII blocked, budget stop, audit row, MCP tool denied); README comparison table.
- Days 15-30: six honest SEO pages on the docs site (LiteLLM alternative with free SSO; Portkey alternative after the acquisition; Helicone alternative; HIPAA LLM gateway; MCP gateway security; AI audit log for SOC 2), each stating gaps.
- Days 30-45: GitHub launch (Show HN, r/selfhosted, dev.to), good-first-issue labels, GitHub Discussions.
- Days 45-90: ship OTel and SIEM export; publish a sample evidence pack mapping controls to HIPAA/SOC 2 (state it is not legal advice).
- Demo environment: local docker compose first, recorded video second, a mock-data admin build on a static host third. Do not host a persistent free-tier backend (databases sleep or expire; a broken demo costs more than none); hold no customer data.

## Five buyer conversations (20 minutes each; do these before Phase 2)
Find heads of security/platform at health-tech or fintech companies of 100-1,000 people. Ask: 1) How do your teams call LLMs today, and who approved it? 2) What did security ask for before allowing it, and where did you get stuck? 3) Last time someone pasted sensitive data into a prompt, how would you have known? 4) Show the 3-minute demo. 5) What would stop you running this next month? 6) Would you pay, how much, and who signs? Ask for a 30-day design-partner pilot. Log every answer; stop building new features until five are done.
