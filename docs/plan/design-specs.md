# OpenProxyAI — Design Specs for Phases 1-4

Condensed from specialist design agents. Evidence label **[AGENT]** = from an agent reading the code/references, not re-verified. Effort numbers are agent estimates in engineer-days. Re-check each premise against the code before implementing (see `execution-plan.md` rule 6). References are in `references/` (read-only, design ideas only, never copy code).

Common rules for every spec: new tables get `org_id`, `ENABLE`+`FORCE` RLS, an org policy, and app-role grants; one new migration per change on the current head (`alembic heads`); sidecars never raise; logging via background tasks; each feature ships with fake-upstream tests.

## §A. MCP and agent security (Phase 1) — about 32.5 days total; items 1-7 are the MVP (15.5)

Audit findings [AGENT]: no caller-token passthrough (good); one shared upstream credential per server (confused deputy); upstream error text echoed to the agent; `Mcp-Session-Id` issued but never validated; SSRF check validates but httpx resolves again (DNS-rebinding window); redirects rejected only by accident; no response-size cap and per-phase (not total) timeout; no `Origin` check; `ApiKey.permissions` ignored for MCP; no rate limit/budget on MCP; policy is one org-wide allow/block list; tool descriptions fetched live (no pinning); no hashes in audit; `tools/list` not audited.

Work items:
1. Transport/SSRF hardening (2d): resolve once off the event loop (`asyncio.to_thread`) and connect to the validated IP with the original Host/SNI; reject 3xx explicitly; stream the body with `max_response_bytes` (default 2 MB); total deadline with `asyncio.timeout(timeout_s)`; send DELETE to close upstream sessions; validate `Origin` against an allowlist (missing Origin allowed for non-browser clients); require `proxy:mcp` in key permissions; apply the rate limiter; return generic upstream errors.
2. Malicious fixture (1.5d): `tests/fixtures/malicious_mcp.py` (Starlette ASGI app) with modes: description changes after N lists (rug-pull); `<IMPORTANT>`/Unicode-tag poisoned descriptions; injection in results; 50 MB body; 1 byte/s SSE drip; 302 to 169.254.169.254; resolver returning public then 127.0.0.1; header echo (assert no `opai_` or client headers reach upstream); injected error message; 10k tools; `__` in tool names.
3. Pinning and drift (3d): tables `mcp_tools(name, description, input_schema, annotations snapshot, current_hash, approved_hash, status pending|approved|drifted|blocked, input_policy, output_trust, is_write, requires_approval)` and `mcp_tool_versions`. Hash = sha256 of canonical JSON. `tools/list` serves the pinned snapshot, never the live description. On call, live hash != approved hash marks `drifted`; `pin_mode` off|warn|enforce (default warn) blocks in enforce with JSON-RPC -32004. Sync on admin request and every 15 min.
4. Output/description scanning (2d): size cap, then existing injection model + response guardrails + heuristics (Unicode tag chars U+E0000-E007F, zero-width chars, "ignore previous"/`<IMPORTANT>`, markdown image exfil URLs, long base64). Modes off|log|redact|block.
5. Grants and narrowing (2.5d): `tool_grants(subject_type role|team|user|api_key|agent, subject_id, tool_pattern, effect)`, deny wins; org policy stays the outer cap. Request header `X-OpenProxy-MCP-Tools` can only narrow, never widen; malformed → 400. Write the effective set to the audit row. Property-test that narrowing never widens.
6. Virtual bundles (2d): `mcp_bundles`, `mcp_bundle_tools`, `api_key_mcp_bundles`; `POST /v1/mcp/{slug}` requires the key to be attached.
7. Taint and session binding (2.5d): Redis `mcp:sess:{id} -> {api_key_id, tainted}`; a tool with untrusted output taints the session; a `trusted`-input (sink) tool in a tainted or session-less call is blocked or sent to approval. Apply the same check to `role=tool` messages on chat completions. Model after LiteLLM's tool_policy guardrail idea (read-only reference).

Later (items 8-12): human approval for write tools (`mcp_approvals`, JSON-RPC -32003, single-use, bound to `args_sha256`, 15-min expiry) 3d; agent registry + kill switch (<1 s via Redis pub/sub) + A2A card pinning 3d; `/.well-known/oauth-protected-resource` + JWT audience binding (RFC 9728/8707) 3d; MCP 2026-07-28 support (`server/discover`, header checks, keep upstream hop on 2025-11-25) 3d [spec details AGENT-reported; confirm against the spec]; console UI 5d.

Threat mapping (OWASP Agentic IDs from memory, verify): pinning/drift → supply chain/tool poisoning (ASI04); output scan + taint → goal hijack/context poisoning (ASI01, ASI06); grants/bundles/narrowing → tool misuse/privilege abuse (ASI02, ASI03); approvals → ASI02, ASI09; audience binding/no passthrough → confused deputy (ASI03); SSRF/caps → ASI08; agent identity/kill switch → ASI10, ASI07.

Risks: strict pinning causes friction (default warn); scanner false positives; clients dropping the session id (no session counts as tainted for sink tools); IP pinning may break some TLS/proxy setups; per-user upstream OAuth depends on IdP support for RFC 8707/8693.

## §B. Policy layer v2 and classification-aware routing (Phase 2) — about 30 days; MVP about 17

Prerequisite fixes (Phase 0): cache-embedding leak (P0-2), env-key region (P0-3), inline logging (P0-7), status code (P0-6). Additional gaps [AGENT]: no `api_base` on `LLMProviderKey` (nothing can route to vLLM/Ollama/private endpoints; confirmed absent from `backend/app` [CHECKED]); fallback model header only checked against the allowlist, not re-run through full policy; policy is one fixed sequence with one org-wide mode and no per-key/team bindings; Presidio runs synchronously on the event loop.

Design:
- Guardrail plugins: `manifest.json` per plugin (id, functions, `supportedHooks`, JSON-Schema `parameters` that also drives the admin form, plus `transform_capable`, `preview_safe`, `timeout_ms`). Hooks: `pre_request`, `classify`, `pre_route`, `post_response`, `stream_chunk`, `tool_pre_invoke`. Modes: off, log_only, enforce, transform. Built-ins fail closed; external adapters follow a per-binding `on_error`. Execution by priority, same-priority non-transform plugins concurrently. Verdict = `{action, reason_code, data_class?, transformed?, evidence}`.
- Bindings table with scopes org/team/api_key, most specific wins, org may mark a binding `locked`. `POST /v1/policy/preview` runs the chain and router with no upstream call and no log; per-binding `shadow=true` logs verdicts without blocking.
- Adapters: HMAC-signed webhook (reuse the webhook SSRF guard), Bedrock Guardrails (`ApplyGuardrail`), Azure Content Safety. In AIRGAP_MODE external adapters are refused at save time.
- Expression language: CEL. Measured [AGENT]: pure-Python `cel-python` about 368 µs per eval; Rust-backed `common-expression-language` about 9 µs. Use the Rust binding behind an `ExprEngine` interface with the pure-Python fallback; compile once, cache by `(rule_id, updated_at)`, validate at save time. OPA/Cedar only as optional external adapters.
- Data classes `public < internal < confidential < secret`. The effective class is the maximum of the key/team default, the user-asserted `x-openproxy-data-class` header (may only raise), and classifier plugins (per-org `class_map`, e.g. `US_SSN` → confidential).
- `model_registry` (org_id, model_id, provider, provider_key_id, `api_base`, `max_data_class`, `regions[]`, `risk_rating`, `retention_days`, `trains_on_data`, `internal`, `capabilities[]`, `cost_tier`, `owner`, `enabled`). `llm_provider_keys` gains `api_base`, `max_data_class` (default `internal`), `is_internal`.
- Router: authorized set = registry ∩ allowlist ∩ `max_data_class >= class` ∩ region ∩ risk ≤ org max ∩ CEL authz. A concrete model must be in the set; `model: "cap:CODE_GENERATION"` is matched by capability. Existing key selection/weights/adaptive LB/circuit breaker run inside the set only. **Every fallback — fallback header, experiment variants, env keys, cache embeddings, streaming retries — must come from the same authorized set.** If the set is empty: policy-block status (446 once D6 is decided) with `reason=no_authorized_model`, zero upstream calls, no silent downgrade.
- Explainability: response headers `X-OpenProxyAI-Data-Class`, `-Route-Model`, `-Route-Reason`, `-Policy-Trace-Id`; block bodies carry a user-facing `user_message`; a `routing_decision` record in `request_metadata`.
- Pipeline order: Auth → Classify + pre_request plugins → Rate limit → Route → Cache (class-aware keys) → LiteLLM → post_response plugins → Log (background).
- Tables: `guardrail_bindings`, `model_registry`, `routing_rules(priority, cel, target, mode)`, `data_class_policies`. Backfill `org.settings.policy` into bindings; keep `PolicyConfig` as a read-compatible shim for one release.
- Endpoints: CRUD `/api/v1/guardrails/bindings`, `/api/v1/model-registry`, `/api/v1/routing-rules`; `GET /api/v1/plugins`; `POST /v1/policy/preview`; `POST /api/v1/routing-rules/validate`.

Work items: leak/rule fixes 2d; migration + registry + `api_base` 3d; `expr_engine` 2d; classification service 2d; router + fallback closure 4d; plugin runner/manifests/port built-ins 4d; bindings + preview/shadow 3d; adapters 3d; admin UI 5d; capability routing + conditional rules 2d.

Tests: Hypothesis property tests — random registries, data classes, regions, failing upstreams, random fallback headers/experiments; fake upstream records every `(model, api_base, key_id)`; assert every call (completion, fallbacks, cache embedding) satisfies `max_data_class >= class` and region, and an empty set yields the block status with zero upstream calls. Plus: header can never lower the class; scope precedence and `locked`; org A's registry invisible to org B; preview makes no upstream call and writes no log; shadow logs but never blocks; a diff test of old policy engine vs shim.

## §C. API surface, performance, telemetry (Phases 1 and 3) — about 30 days

Verified in code [CHECKED]: only 3 LLM routes; `Message` schema gap (P0-4); no `include_usage` (P0-5); policy block status 403 (P0-6); inline `await log_request` (P0-7). [AGENT]: hot path about 6-8 Postgres and 6-12 Redis round trips per request (not measured), including a `last_used_at` write on every request and sequential per-key circuit-breaker/adaptive-LB Redis calls.

Order and effort: schema/streaming/status fixes 2d (Phase 0); perf harness + fake upstream 2d (shared with P0-8); hot-path caching 3d (auth result cached ~30 s in Redis, batched `last_used_at`, per-org provider-key and experiment cache with invalidation, one Redis pipeline for per-key checks); pipeline refactor into modality-neutral steps with per-endpoint adapters (`extract_text`, `estimate_cost`, `call`, `usage_from`, `cacheable`) 3d; `/v1/responses` 3d (block `previous_response_id`/`store=true` by default — provider-side state conflicts with residency; policy flag); `/v1/rerank` 1d; OTel 3d; SIEM 3d; audio transcriptions/speech 3d; images 2d (never cache; keep `b64_json` out of logs); files/batches 5d (`batch_jobs` table, poll job, per-line policy scan, budget pre-reserve); realtime deferred. LiteLLM functions exist in the pinned reference copy: `aresponses`, `aimage_generation`, `atranscription`, `aspeech`, `arerank`, batches API; realtime is private.

OpenTelemetry [AGENT design]: optional SDK import; `BatchSpanProcessor` with bounded queue; all exporter errors swallowed; root span `gen_ai.{operation} {model}` with `gen_ai.operation.name`, `gen_ai.provider.name`, `gen_ai.request.model`, `gen_ai.response.model`, `gen_ai.usage.*` (input/output/cache_read/reasoning tokens), cost; child spans auth, rate_limit, policy, cache, provider.call (fallback attempts as events), mcp.tool; content capture off by default (`OTEL_CAPTURE_CONTENT=false`); `org_id` on spans only (never metrics, cardinality). Flags `OTEL_ENABLED`, `OTEL_EXPORTER_OTLP_ENDPOINT/PROTOCOL/HEADERS`, `OTEL_SAMPLE_RATIO`. In AIRGAP_MODE only internal endpoints are allowed. Propagate inbound W3C `traceparent`.

SIEM [AGENT design]: bounded queue + worker, retry then dead-letter, `submit_event()` uses `put_nowait` and never raises, counts drops. Events `AI-DLP-BLOCK`, `AI-POLICY-BLOCK`, `AI-UNAUTHORIZED-MCP`, `AI-PROMPT-INJECTION`, `AI-BUDGET-EXCEEDED`, `AI-RATE-LIMIT`, `AI-KEY-REVOKED-USE`. Formats: CEF over syslog (RFC 5424, TCP+TLS/UDP), JSON over HTTPS (Splunk HEC/Elastic), OTel logs. Per-org destinations in `org.settings.siem`, secrets encrypted; gate behind a plan feature. CEF escaping tests for `|`, `=`, `\`.

Performance targets (realistic for Python, to be measured): added latency p50 < 5 ms, p99 < 15 ms with cache and Presidio off; 500-1,000 RPS per 4-vCPU pod. Do not rewrite in Go/Rust; publish measured numbers. Harness: k6 scripts in `deploy/perf/` against the fake upstream, `pytest-benchmark` for policy/key selection, CI smoke with a 20% regression gate.

Risks: LiteLLM API churn (pin + contract tests); batches break request/response accounting; buffered stream guardrails trade TTFT for safety; `get_db` may hold a connection for the whole stream (measure under load; unverified).

## §D. Eval loop and conversation workspace (Phases 3-4) — about 26 days (SQL view optional)

Today [AGENT, partly CHECKED]: `eval_service.py` runs one hook after experiment requests (HTTPS callback or fixed 1-5 LLM judge), fails open; `POST /api/v1/requests/{id}/scores` needs a JWT user, so API-key apps cannot call it; `request_logs` holds metadata only, no prompt/response text; experiments pick variants by weighted random choice, never stop, and results are matched by model name so two variants with the same model collide; prompt templates are versioned but cannot be promoted.

Eval loop (about 12-13 days): (1) fix `request_scores` RLS (P0-1), add `source`, `comment` (≤2k chars, PII-redacted), `user_id`, `evaluator_id`; `POST /v1/feedback {request_id, score_name, value|thumbs, comment}` behind `ProxyAuth`, idempotent per request+score name, request must belong to the caller's org (1.5d). (2) Opt-in `request_payloads(org_id, request_id, messages jsonb, output text, redacted, expires_at)` written in the background after policy redaction only when the org enables `capture_payloads` with a sample rate (default 0); expiry follows `audit_retention_days` (2d). (3) `datasets`/`dataset_items`, import by filter with PII-safe sampling, refuse rows marked `pii_detected` (2d). (4) `evaluators(type exact|regex|llm_judge)`, offline `POST /api/v1/eval-runs`, judge uses the gateway's own key rotation so it is metered and policy-checked, minimum 20 datapoints before stopping (3d). (5) Adaptive A/B: `mode static|adaptive`, `metric`, `min_samples_per_variant`, `delta`, `winner_variant_id`, `stopped_reason`; 5-minute job updates weights with a floor and stops with a confidence bound; key variants by `variant_id`, not model name (3d). (6) Promotion gate: `prompt_templates.status draft|candidate|active`; promote requires a passing eval run unless an admin overrides (override audited) (1.5d). Optional: read-only SQL view as `app_user` with `SET TRANSACTION READ ONLY`, 5 s timeout, parser-validated single SELECT on `v_requests`/`v_scores`/`v_spend` (2.5d; can be cut).
Tests: cross-org score read/upsert blocked; feedback works with an API key and rejects out-of-range values; sample rate 0 stores nothing; expired payload rows deleted; import skips PII rows; seeded-Bernoulli simulation converges and stops with a winner and never stops below `min_samples`; promotion returns 409 without a passing run.

Conversation workspace (about 10.5 days). Defer: team/enterprise/facts/RAG memory tiers, feedback-to-knowledge pipeline, capability taxonomies, personas, enterprise-level sharing, a separate chat site, voice. Build: `conversations(owner_user_id, team_id, title, visibility private|team, classification public|internal|confidential, system_prompt, deleted_at)`, `conversation_turns(seq, role, content (redacted copy), model, provider, request_id, classification)`, `context_packages(turn_id, model, provider, included_turn_ids, excluded_turn_ids, exclusion_reasons, token_count, content_hash)` (append-only), `conversation_tags`. RLS needs a second rule on top of org (`owner_user_id = current user` or team visibility), so add `set_session_user_id()` next to `set_session_org_id()` in `database.py`. Endpoint `POST /api/v1/conversations/{id}/turns {content, model?}`: load turns → classify the new message → store the turn → **settle the final model first (including experiment variant and fallback)** → build the context package from turns at or below that model's `max_data_class`, trim to a token budget → write `context_packages` → call the normal chat pipeline → store the reply. UI: `features/chat/` in the admin console (list, thread, per-turn model picker, tag chips, "context sent" drawer); streaming in a later phase.
**Critical risk:** fallbacks and experiments can change the model after the context was built, leaking confidential turns. Rebuild the package for each fallback candidate or allow only fallbacks with equal or higher clearance; never fall back silently to an unauthorized model (return the block status with a user-facing explanation). Required tests with a fake upstream that records what it receives: switching openai → anthropic → mistral mid-conversation keeps ordering and the full allowed history; a confidential turn plus a model cleared only to `internal` never receives the confidential text (substring and hash check) and `excluded_turn_ids` lists it; a forced primary failure with an under-cleared fallback is refused or gets a rebuilt package; an experiment variant also respects clearance; a second user cannot see a private conversation.

## §E. Admin console and website UI plan (Phase 1) — estimate 10-15 days [AGENT audit; 6 of 28 screenshots reviewed]

Findings: admin-console typecheck/build OK, 11 vitest tests, **no lint config**, 891 KB single JS chunk; web-app has 8 lint errors (mostly shadcn files; one real: `Math.random` during render in `sidebar.tsx`) and the package is named `my-app`. Admin design is warm cream with pastel blobs, clashing with the dark website; the 208 px sidebar never collapses so the console is unusable on mobile; dashboard number formatting is poor (`$0.000`..`$2000.000`, no thousands separators); policy page is one long form; icon-only actions lack labels; website mobile has no hamburger and the page is about 7,200 px long.

Tokens/components: adopt the website's dark mono-accent palette as default with a light theme; semantic colours; type scale 12/13/14/16/20/28 with a mono face for IDs/models/numbers; 4 px grid. Build on the existing shadcn/Radix pieces: `PageHeader`, `StatCard` (value, delta, sparkline), `DataTable` (sticky header, density, column picker, URL-synced filters, skeleton/empty/error states), `FilterBar`, `StatusBadge`, `CodeBlock`+`CopyButton`, `Drawer`, `Tabs`, `Waterfall`, `EmptyState`, `ConfirmDialog`, `CommandPalette`; shared currency/token/duration formatters.

Priorities: (1) responsive drawer sidebar under 1024 px; (2) unify visual language with the website and remove the global link underline; (3) MCP servers/tools page (backend exists, no UI); (4) request trace waterfall (auth, rate limit, policy, cache tier, upstream, tokens, cost; replay in playground); (5) provider health/routing page (data already in `ProviderKeyResponse`); (6) rebuilt dashboard (KPI deltas, sparklines, spend by team/key/model, budget burn-down); (7) standard `DataTable` everywhere; (8) nav groups Observe/Govern/Connect/Admin plus ⌘K and breadcrumbs; (9) accessibility pass (labels, focus rings, aria-live toasts, contrast, keyboard drawers); (10) route-based code splitting, ESLint config, Playwright smoke tests; website: hamburger nav, fix lint errors, rename the package.
Missing screens vs competitors: guardrails library with test panel; spend/budget screens; cache analytics; model catalogue; webhooks/integrations; SSO/SCIM setup; data-residency view.
